## 1. 연결 고리(새 매핑 데이터 없음)
- 공정의 공간 노드(source·buffer·sink)는 자산 → 그 공간의 ACCESS 포트, 작업 단계는 후보 설비 → 출발은 OUT·도착은 IN 포트.
- 이동 구간: 위치(자산이 있는 공간, 후보 설비가 있는 작업 단계) 사이를 위치 없는 노드(완료 표시·합류·작업자 단계)를 거쳐 잇는다.
  운반 단계(transport_manual)를 지나면 운반 자원 이동(`transport`), 아니면 사람 이동(`move`, 간선의 `movement_rule.mode`).
- 후보 설비가 여러 대(택1)면 포트 쌍이 여러 개다. 경로는 0.18.0의 `/paths`와 같은 계산(고정 경로 우선, 통로 그물 최단 경로).

## 2. PR A — 계약 0.19.0(추가만), 엔진 결과 불변
- `GET /layout-versions/{v}/process-links?process_version_id=…(반복, 생략하면 제품마다 현재 승인본)&scenario_version_id=…`:
  공정마다 이동 구간 → 포트 쌍 → 경로·길이·이동 시간(길이 ÷ 속도, 운반은 + 상하차). 저장하지 않으므로 공정·배치판·설정을 고치면 자동 재계산.
- 시나리오 버전: `layout_version_id`(이 프로젝트의 **승인된** 배치판, 선택, SCN-REF-005·006), `travel_rule`
  = `{speeds_kmh: {키: km/h}, carrier_handling_minutes}`. 키는 사람 `person`, 운반 자원은 그 설비의 종류(equipment_type) 문자열.
  **비어 있으면 사용자 기본값: 속도 4 km/h(사람·지게차·AMR 모두), 상하차 1분.** 승인 후 동결(트리거 갱신).
- 시나리오 갱신(refresh)에 `layout`(latest 기본 | keep): 배치판을 고른 초안이면 최근 승인 배치판으로 바꾸고 `layout_change`로 알린다.

## 3. PR B — 엔진 반영(결과가 바뀐다, 엔진 버전 올림)
- 시나리오가 배치판을 고르면 실행 입력 스냅샷에 배치판(점·통로·고정 경로·포트 매핑)과 이동 설정을 고정한다(재현성).
- 운반 단계: 1건 시간 = 상하차 + (출발 공간 ACCESS → 도착 공간 ACCESS 경로 길이 ÷ 그 운반 자원 종류의 속도). 운반 자원이 다른 곳에서
  일을 받으면 빈 차 이동 = 그 자원의 현재 위치 → 출발 공간 경로 길이 ÷ 속도(시나리오 가정 `carrier_empty_move_minutes` 대신).
- 사람 이동: 간선 이동 조건이 `network_route`인 구간만 길이 ÷ 사람 속도만큼 걸린다(그 밖의 사람 이동은 지금처럼 시간 없음 —
  사용자 결정 2026-10-28 "공간 사이 이동은 사람이 그냥 옮기는 것이라 일단 시간 고려 없이").
- 경로를 찾을 수 없으면 사전검증 오류(실행 불가), 기본값을 쓰면 사용한 가정으로 보고한다.
- 배치판을 고르지 않은 시나리오는 지금과 같다(결과 불변).
