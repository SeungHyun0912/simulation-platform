# CR-backend-20261027-be11-asset-timeline
- 요청자: Backend / 작업 BE-11(임시 ID, 결과 분석 API 3종 중 둘째) / 대상: contracts/04 §5(실행 결과 API)
- 상태: **사용자 지시로 진행**("후보로 정해준 API들을 순서대로 개발해 줘", 2026-10-27 — 둘째 후보 "설비 상태 타임라인 요약 API"). API 담당이 권장안 승인으로 해석, 정정 가능.
- 선행: CR be10 / 계약 0.12.0(PR #54). **계약 0.13.0은 0.12.0이 main에 게시된 뒤 승격한다.**

## 1. 왜 필요한가
지표는 구간 합계라 "설비가 언제 일하고 언제 놀았는가"를 시간축으로 볼 수 없고, 이벤트를 전부 읽어야 간트를 그릴 수 있다(6공정 한 달치 16만 건). 또 사용 기록이 없는 후보 설비는 지표 행이 없어 "놀고 있는 설비"를 화면이 알 수 없었다.

## 2. 범위(계약 0.13.0, 추가만, migration 없음)
1. `GET /projects/{p}/runs/{r}/asset-timeline?window=day|week|month|run`(viewer): 설비마다 구간별 상태 시간 구성 — 처리·준비·예약·막힘·**유휴(= 구간 길이 − 나머지)**·가동률. 공정의 후보 설비 전체를 보여 주며 사용 기록이 없으면 `used: false`, 전 구간 유휴. 각 설비를 어느 제품·단계가 쓰는지(`uses`). 설비 코드 순 cursor 페이지.
2. `GET /projects/{p}/runs/{r}/assets/{asset_id}/states?from_min&to_min`(viewer): 설비 하나의 상태 구간(간트) — 상태·시작·끝·길이·작업·단계·제품. 길이 0인 전이는 뺀다. 마지막 구간은 실행 종료 시각까지. `event_seq` cursor 페이지.
- 둘 다 공식 결과(선택된 시도)만, 없으면 409 `RUN_RESULT_NOT_AVAILABLE`.

## 3. 원칙
- 값은 이미 저장된 지표(구간별 상태 시간)와 이벤트에서 읽는다(새 계산 규칙 없음). 유휴는 "설비 상태 이벤트 기준으로 일하지 않은 시간"이며 가동 달력이 없어 24시간 기준이다.
- 운반 설비(지게차·AMR)는 엔진이 자원으로 모델링하지 않아 타임라인에 없다.
