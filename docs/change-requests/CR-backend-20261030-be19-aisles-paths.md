# CR-backend-20261030-be19-aisles-paths
- 요청자: Backend / 작업 BE-22(임시 ID) / 대상: ERD §7(배치), contracts/04 §7.1(scope `layouts`) 확장
- 상태: **사용자 지시**(2026-10-30) "방법1 구조로 진행해 줘. 일방통행은 없어. … 운반 시간은 나중에 별도로 두고 변경할 때마다 계산이 자동으로 될 수 있게만 해주면 좋겠어."
- 선행: 계약 0.17.0(PR #68 머지). migration head 0011 → 0012.

## 1. 왜 필요한가
경로(R)는 포트 → 포트 한 쌍이라, 다음 공정 설비가 여러 대(예: ST-004 → 실리콘 편조기 EQ-003~010 택1, CU 편조기 42대)면 공정 쌍마다 "출발 × 후보 설비 수"만큼 경로를 그려야 한다.

## 2. 사용자 확정 구조(2026-10-30)
- **P(점)**: x·y. 포트 위치·꺾이는 곳·갈림길(기존).
- **W(통로)**: 다닐 수 있는 선 = 점 순서 배열, 포트에 묶이지 않는다. 꺾임은 점을 더 넣어 한 줄로, 갈림길·교차로는 **같은 점을 공유**해 잇는다(십자는 가로·세로 통로가 가운데 점을 함께 지나는 방법 1). **모두 양방향**(일방통행 없음).
- **R(경로)**: 포트 → 포트의 실제 길. **보통은 서버가 계산**(P·W·고정 경로의 선분을 모은 길 그물에서 최단 경로), 특정 쌍을 정한 길로만 다니게 하려면 지금처럼 고정 경로를 저장하고 계산보다 우선한다.

## 3. 변경
- DB(0012): `layout_aisle`(`aisle_key`·`attributes`), `layout_aisle_point`(통로의 점 순서). 같은 배치판의 점만 참조, 승인 후 동결(기존 트리거 함수 재사용).
- API(계약 0.18.0, 추가만):
  - `PUT …/content`·`GET …/{v}`에 `aisles[]`(`aisle_key`·`points`·`attributes`, 응답에 계산한 `length_m`). 보내지 않으면 빈 목록(기존 클라이언트는 통로를 지우게 되므로 FE는 응답의 `aisles`를 그대로 다시 보낸다).
  - `POST …/{v}/paths`(viewer, 저장 안 함): `pairs[]`(`from_port_id`·`to_port_id`, 최대 500) → 쌍마다 `reachable`·`source`(fixed | computed)·`points`(점 key 배열)·`length_m`·`route_key`(고정 경로면). 출발·도착 포트가 점에 매핑되지 않았거나 길이 없으면 `reachable=false`와 이유.
- 길 그물: 통로·고정 경로의 이웃한 점 쌍이 양방향 선분, 길이 = 직선 거리. 최단 경로(Dijkstra), 같은 길이면 점 key 순으로 결정적. 결과는 저장하지 않으므로 점·통로를 고치면 다음 조회부터 자동으로 바뀐다.
- 저장 오류(422): 통로 key 중복(`LAY-SAVE-011`), 통로 점 2개 미만·연달아 같은 점·없는 점(기존 008·009·003을 `/aisles/i`에).
- 검증 경고: `LAY-008` 선분이 겹치는데 공유 점이 없음(이어지지 않은 교차), `LAY-009` 포트의 점이 어떤 통로·경로에도 닿지 않음(도달 불가).

## 4. 범위 밖(후속)
- 사람·지게차·AMR 속도와 운반 시간(= 거리 ÷ 속도) — 속도를 정하면 같은 길 계산으로 자동 산출.
- 엔진이 경로 시간을 쓰는 것(지금 운반은 고정 3분 + 싣기·내리기 1분), 시나리오의 배치판 선택.
