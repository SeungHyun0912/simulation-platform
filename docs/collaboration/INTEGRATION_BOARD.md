문서 버전: 1.0

권장 경로: docs/collaboration/INTEGRATION_BOARD.md

## 1. 운영 원칙
- API, UI, 통합 검증 세션 모두 작업 전 최신 파일과 Git 상태를 확인한다.
- 이 문서는 작업·인계의 기준이며 API 계약이나 도메인 명세를 대체하지 않는다.
- 각 작업의 책임자는 한 역할로 지정한다. 여러 영역이면 하위 작업으로 나눈다.
- 한 파일을 여러 세션이 동시에 수정하지 않는다. 편집은 순차 예약하고 저장 직전 diff를 확인한다.
- 별도 브랜치에서는 문서 변경도 병합해야 다른 세션에서 보인다. 자동 동기화를 가정하지 않는다.
- 잠금 표시는 협업 약속일 뿐 실제 파일 잠금이 아니다. 강제 잠금·원자적 수정 기능이 없다.
- 같은 작업 디렉터리에서 다른 세션의 파일·브랜치·미커밋 변경을 되돌리지 않는다.
- 비밀값, 실제 개인정보, 인증 토큰은 기록하지 않는다. 로그는 필요한 범위만 마스킹한다.
- 코드 줄 번호만이 아니라 커밋과 파일 경로를 함께 기록한다.
- 미실행·차단을 통과로 보고하지 않는다. Mock 통과와 실제 API 통과를 구분한다.

## 4. 상태·우선순위
작업 상태:
제안 → 승인대기 → 준비 → 진행 → 구현완료 → 검증대기 → 검증중 → 완료
예외 상태: 차단 / 재작업 / 취소

- 준비: 요구·수용 기준·담당·선행 조건이 합의됨.
- 구현완료: 담당자의 자체 검사 완료. 통합 검증 통과는 아님.
- 검증대기: 수정 커밋과 재현·자체 검사 증거를 인계함.
- 완료: 합의한 수용 기준을 지정 환경에서 검증하고 증거를 남김.
- 검증 실패는 재작업으로 돌리고 회차별 결과를 보존함.
- 테스트 판정은 작업 상태와 별도: 통과 / 실패 / 차단 / 미실행 / 해당 없음.
- 우선순위 P0: 격리·보안·데이터 손실 위험, P1: 핵심 흐름 차단, P2: 일반 기능 문제, P3: 개선.
- 심각도와 처리 우선순위는 같지 않을 수 있다. 우선순위 최종 결정은 조정자.

## 10. 통합 검증 세션 시작 지시문
이 저장소는 FastAPI 백엔드와 React 프런트엔드를 포함한 프로젝트 기반
시뮬레이션 플랫폼이다. 너는 통합 검증 담당이며, API와 UI 개발은 별도 세션에서 진행한다.

1. 루트 README.md, AGENTS.md, 영역별 지침, ERD, 승인된 API 계약,
   도메인 규칙, 상태·인계 문서, 이 작업 보드를 읽는다.
2. 기존 코드와 Git 상태를 확인하고 문서와 구현의 불일치를 보고한다.
3. 첫 응답은 분석과 검증 계획까지만 작성한다.
   대상 커밋·계약, 환경 준비 상태, 검증 범위, 재현 가능한 기대 결과,
   수정 예정 파일, 승인·결정 필요 사항을 제시한다.
4. 검증 기준이 불명확하면 사용자에게 묻는다. 개발 세션의 구현을
   그 자체로 정답으로 삼거나 미정값을 임의로 채우지 않는다.
5. 승인 후 격리된 테스트 환경에서 UI→API→DB 흐름을 검증한다.
   운영 DB·사용자의 실제 공정 데이터를 사용하거나 초기화하지 않는다.
6. 테스트 환경에서 실제 API를 사용하는지 확인한다. Mock 기반 검사와
   실제 연동 검사를 별도로 기록한다.
7. 결함은 재현 절차·요청/응답·로그·화면 증거와 함께 이 보드에 기록한다.
   원인이 불명확하면 담당을 추정 확정하지 않고 공동 진단을 요청한다.
8. 제품 코드는 기본적으로 읽기 전용이다. 계약·ERD·기대값은 수정하지 않는다.
   자동화 테스트는 승인된 테스트 폴더에만 작성한다.
   API/UI 수정이 필요하면 담당 작업으로 인계한다.
9. 다른 세션과 같은 파일을 동시에 편집하지 않는다. 편집 예약을 확인하고
   문서 수정 직전 최신 내용을 읽어 자신의 변경만 반영한다.
   공용 작업 폴더의 브랜치 전환·reset·clean·stash·병합은 승인 없이 하지 않는다.
10. 수정 인계 후 수정 커밋과 동일한 재현 조건으로 재검증한다.
    관련 정상 흐름·권한·데이터 보존 회귀 검사도 포함한다.
11. 모든 결과는 통과/실패/차단/미실행을 구분한다.
    실행하지 않은 테스트를 통과로 보고하지 않는다.
12. 종료 시 검증 커밋·계약·환경, 결과 요약, 증거 경로, 남은 결함,
    API/UI별 다음 작업을 기록한다. 임의의 자동 재실행이나
    다른 세션에 전달 완료했다고 주장하지 않는다.
    사용자가 전달할 세션별 메시지도 별도로 출력한다.

## 11. API·UI 개발 세션에 추가할 공통 지시
- 작업 시작·종료 및 새 단계 착수 전 이 보드를 다시 읽는다.
- 본인에게 승인된 작업만 진행하고 선행 작업·계약 변경 여부를 확인한다.
- 결함 수정 전 재현 여부와 원인을 기록한다.
- 구현완료 시 수정 커밋·자체 검사·API/UI 영향·재검증 방법을 남긴다.
- 자체 테스트 통과만으로 통합 작업을 완료 처리하지 않는다.
- 계약 변경은 결정 요청을 먼저 등록하고 승인을 기다린다.
- 다른 역할의 테스트 판정이나 증거를 덮어쓰지 않는다.
- 공유 문서 편집은 순차 수행하고, 수정한 문서는 상대에게 전달 가능한
  브랜치·커밋 또는 동기화 경로와 함께 보고한다.
