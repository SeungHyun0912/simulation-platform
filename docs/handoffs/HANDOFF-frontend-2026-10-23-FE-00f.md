## 실제 구현 내용 (정적·예시 데이터, API 호출 없음)
- 공정 표 편집 화면 `/projects/:projectId/products/:productId/processes/:versionId`.
  - 단계 표: 순서, 공정명, 설비(후보 그룹/특정 지정), 처리, 준비, 산출, 다음 위치, 확인 상태, 작업(편집·위/아래 이동·삭제).
  - 단계 추가, 이동, 삭제(확인 대화상자). 삭제는 이 화면의 편집 내용만 바꾼다.
  - 선택한 단계를 편집하는 패널: 공정명, 확인 상태, 설비 배정 방식·후보, 처리 방식(없음/산출 선속/산출 단위당 시간/기준 길이당 시간/미정), 준비 시점·시간, 산출 방식(수량 지정/길이 분할/유지/미정), 다음 위치.
  - 편집을 열면 제목으로 포커스가 이동하고, 닫으면 편집을 시작한 버튼으로 돌아온다.
  - 승인·검토 중인 버전은 읽기 전용(편집·이동·삭제·추가 숨김, 입력 비활성).
  - 로딩/오류/권한 없음/수정 충돌/찾을 수 없음/단계 없음 상태. 미저장 변경은 이동·프로젝트 전환 전에 확인.
- 제품 상세의 버전 표에서 "공정 편집/보기 (초안 UI)" 링크로 연결.
- 값 표현: 선속(m/분)은 산출 길이(m)·보빈 수와 별개 단위로 입력하며, 처리 방식을 바꿔 단위가 달라지면 이전 값을 이어받지 않는다. 미정은 0이 아니다(0분은 유효). 기준 길이당 시간은 비례 계산하지 않는다는 안내를 표시.
- 공통 컴포넌트 변경: `ValidationPanel`(오류는 항상 펼침, 경고가 3건을 넘으면 접음), `DataTable`(`wrapCells`로 셀 줄바꿈·한글 단어 단위), `knownValueText`(값 요약 문구 공통화; `capacityText`가 위임).
- 검증 경로는 내부 UUID 대신 표의 순서 번호를 사용(`/steps/2/setup/duration`).

## 채택 결정과 근거
- 표는 요약 보기와 단계별 편집 패널로 나눴다. 열이 9개라 셀 안에서 직접 편집하면 키보드 조작과 가로 스크롤이 어려워지기 때문이다. 06 기술서 §6의 "표 편집"을 이 방식으로 해석했다(확인 필요).
- 06 §6 열 중 입력 길이·중량·수량·가닥, 이동, 잔량은 구현하지 않았다. 03 계약에서 입력 규칙(§5), 잔량(§6), 이동(§7)의 필드가 아직 제안 수준이고 규칙 조합이 많아, 이번 범위(처리 시간·준비·산출·다음 위치)에서 제외했다.
- 산출 방식은 4가지(미정, 수량 지정, 길이 분할, 유지)만 넣었다. 가닥 합류·중량 단위 산출은 필드 규칙이 미정이라 제외하고 화면에 안내했다.
- 설비 후보와 다음 위치는 예시 자산(`sampleAssets`)에서 고른다. 같은 설비를 여러 단계에서 골라도 하나의 자원이라는 안내를 표시.

## 미정 또는 임시 가정
- `StepView`는 화면용 뷰 모델이며 DTO가 아니다. 03 계약이 승인되면 필드·열거값·field_meta 표현이 바뀔 수 있다.
- `ProcessingKind`, `SetupTrigger`는 03 §4의 값 목록을 따랐다. 처리 방식 `unknown`은 계약의 값이 아니라 화면에서 "미정"을 표현하기 위한 값이다.
- "확인 상태"(확인됨/미확인/가정)는 03 §2의 값 상태(confirmed/unknown/assumed)를 단계 단위로 단순화한 것이다. 계약은 필드 단위(field_meta)이므로 매핑 방식이 달라질 수 있다.
- 서버 검증(`/validate`)과 화면 검증의 구분: 화면은 형식만 검사하고 "실행 가능" 판정을 하지 않는다.
- 로드맵 ID: 11번 문서에서 해당 항목을 확인하지 못해 관련 로드맵 ID를 특정하지 않았다.
