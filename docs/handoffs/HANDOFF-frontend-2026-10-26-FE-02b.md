## 구현한 것
**모델 (`processDoc.ts`, `processGraph.ts`)**
- 일반 그래프 연산: `addNode`·`patchNode`·`removeNode`·`moveNodeOrder`, `addEdge`·`patchEdge`·`removeEdge`, `hasEdge`, `movementOf`. 노드 삭제는 연결된 간선만 함께 지우고 **앞뒤를 자동으로 잇지 않는다**. 키(`node_key`·`edge_key`)는 자동 생성하고 만든 뒤 바꾸지 않는다. 간선을 추가할 때 이동 규칙은 보내지 않아 서버 기본(미정)이 된다.
- `validateGraphStructure`/`edgeProblem`: 서버 구조 오류와 같은 규칙(자기 간선, 끝에서 나가는·시작으로 들어오는 물류 간선, 키 중복, 빈 이름, 이동 시간 형식)을 저장 전에 알린다. 순환(재작업)은 막지 않는다.
- `layoutGraph`: 왼쪽에서 오른쪽 층 배치(되돌림 간선 처리, 같은 층은 앞 층 평균 위치와 표시 순서). 좌표는 서버에 저장하지 않는다(editor-state는 계약 제안 단계).
**화면 (`GraphEditor.tsx`, `GraphDiagram.tsx`)**
- "그래프 구성" 구역: 자동 배치 SVG 도식(노드 클릭·Tab·Enter/Space 선택, 종류는 글자·테두리 모양·선 모양으로도 구분), 노드 추가 폼, 노드 표(순서·종류·이름·키·공간·연결·검증, 편집·▲▼·삭제), 노드 편집(이름, 시작·대기·끝 노드의 공간 — 저장·도킹 공간만), 간선 추가 폼(불가 이유 표시), 간선 표, 간선 편집(시작·끝·종류, **이동 방식**과 이동 시간).
- 작업 노드를 고르면 기존 **단계 편집 패널**이 열리고(내용은 거기서 수정), 직선 공정 표의 단계 추가·삭제·이동·다음 위치는 그대로 직선 전용이다. 분기를 만들면 직선 전용 버튼이 사라지고 안내가 바뀐다.
- 삭제 확인 창은 함께 지워질 간선 목록을 보여 준다. 노드 삭제 시 열려 있던 단계 편집도 닫힌다.
- 이동 방식은 미정이 기본이고 `direct_feed`도 이동 시간을 0으로 채우지 않는다(03 §7). 이동 방식을 미정으로 되돌리면 시간도 미정으로 비운다. 0분은 유효하다.
**기타**
