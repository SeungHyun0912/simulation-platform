## 1. 데이터 규모와 적용 범위

- 설비 96대: 실리콘12, CU/공용76, AL8.
- 저장/대기/도킹 22곳.
- 제품 6종.
- 설비별 실제 IN/OUT·좌표·통로·용량·개별 호기명은 미정.
- EQ 범위는 각각 한 대씩 펼쳐 저장. 공정에는 자원 후보로 연결.
- 제품명에 AL이 들어가도 실리콘 제품3은 AL 신선·집합 경로를 거치지 않는다.
- 공간 ID는 실리콘 편조 공간 삽입 이후 최신 번호다. 옛 ST 번호는 사용 금지.

- ST-010은 제품6에서 사용되므로 더 이상 미사용 공간이 아니다.
- 위 포함 대수는 설비군 후보 기준, 모든 호기의 실제 사용 가능 확정은 아님.

## 9. 시드 작성 규칙

1. 이 문서의 표를 parser가 그대로 읽는 것을 운영 import로 간주하지 않는다.
2. 개발 에이전트가 explicit seed DTO를 만들고 테스트로 표와 대조한다.
3. EQ-001~096 각각 asset 1행 + 포트2개: 설비 포트192개.
4. ST-001~022 각 asset 1행 + ACCESS 최소1개: 초기 공간 포트22개.
5. 합계 자산118, 기본 포트214(공간별 추가 포트 미도입 가정).
6. 제품6개, 공정 버전6개 모두 draft.
7. 제품군 공통 route를 복제하더라도 ID는 독립; 실물 자산은 공유.
8. 후보 qualification/용량/운반 등 UNKNOWN을 확정값으로 덮어쓰지 않음.
9. test fixture의 보정값은 별도 파일/시나리오. 도메인 seed와 분리.
10. 전체 시드 재실행 시 중복 생성 방지, 적용 diff와 정정 근거 기록.

## 11. 완료·검사에서 확정하지 않은 점

P04~P06의 재권취 완료 milestone은 생산완료 집계 기준이다.
검사시간10분과 작업자무제한은 확정이나 불합격/재검사/폐기비율은 제공되지 않았다.
따라서 초기 모델이 검사 소요시간만 반영하면 결과를 “검사 완료”라고 표시하고
실제 품질합격률100%를 검증했다고 표현하지 않는다.
