# AI 개발 에이전트 작업 지침

## 필수 준수

1. 시작 전에 README → 사용자 데이터 → 미정 목록 → ERD → DTO → API 순으로 읽는다.
2. 이 문서에 없는 도메인 조건을 상식으로 채우지 않는다.
3. 제품·설비·공간 코드는 예제 데이터다. `if product == ...`, `if code == "EQ-036"` 분기 금지.
4. `project_id`를 모든 프로젝트 데이터 접근·FK·캐시·파일·LLM 도구 범위에 적용한다.
5. 조직 인증과 프로젝트 권한을 백엔드에서 검증한다. 클라이언트/LLM이 보낸 ID는 권한 증거가 아니다.
6. 출발지 OUT → 도착지 IN, 저장공간 경유, 설비 내부 가공을 별개로 표현한다.
7. 작업물 개수, 길이, 가닥 수, 배치 크기, 산출 목표를 혼용하지 않는다.
8. 원문/명칭은 한국어를 사용한다. 코드 식별자는 영어 허용. 한자·일본어 주석 생성 금지.
   CAD 원본 문자 자체는 증거 보존이 필요하므로 원문을 파괴하지 말고 정규화 표시 필드를 분리한다.
9. 모르는 수치는 `unknown`. 0, 무제한, 미적용은 별도 값.
10. 승인된 공정·배치·시나리오 버전과 실행 스냅샷은 수정하지 않는다.
11. LLM에게 SQL 실행, 임의 Python 실행, 승인 없는 데이터 변경 권한을 주지 않는다.
12. 실물 설비 ID가 같으면 한 실행에서 한 자원이다. 방문 단계 수만큼 복제 금지.
13. 시뮬레이션 시간과 실제 서버 시간을 구분한다.
14. 긴 실행을 HTTP 요청 안이나 FastAPI 단순 응답 후 작업에 맡기지 않는다.
15. 기존 코드·DB·파일이 확인되지 않으면 있다고 주장하지 않는다. 테스트하지 않으면 “미실행”이라고 보고한다.

- [ ] 바꿀 파일·스키마·API·테스트 계획을 짧게 제시
- [ ] 사용자가 승인한 범위만 변경

- 최신 사용자 정정 → 기록된 도메인 결정 → 승인된 ERD/DTO/API 계약 → 기술 제안 → 과거 예시.
- 원본 대화를 볼 수 없으므로 **08/13번 문서와 변경 이력**이 인계 기준이다.
- 충돌 발견 시 원본 값을 보존하고 `decision_pending`으로 보고한다.
- “최신 사용자 정정”을 주장하려면 입력 문서/요청 내용을 근거로 남긴다.

## 작업 단위

한 번에 작은 수직 기능을 완성한다. 예:
프로젝트 설비 생성 API + IN/OUT 원자적 생성 + DB 제약 + 화면 + 권한 테스트.
기능과 무관한 대규모 폴더 개편/패키지 교체/마이그레이션 리셋 금지.

## 반드시 사람에게 질문할 때

- 시나리오에 필요한 미정값을 대신 확정해야 할 때
- 프로젝트 간 실물 설비를 실제로 공유 실행해야 할 때
- 기존 승인 데이터 또는 결과 삭제가 필요할 때
- 개인정보·공장 도면을 외부 LLM으로 전송하려 할 때
- 공정별 생산량 의미가 바뀌거나 단위 변환 근거가 없을 때
- 기존 테이블 대체, 공개 API breaking change, 비용 발생 외부 서비스 도입
